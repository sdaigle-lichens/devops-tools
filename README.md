# DevOps Tools

A desktop app that draws your AWS architecture from your Terraform, and a Claude Code plugin that
generates the model it draws.

**It is read-only.** It never edits a `.tf` file, never calls AWS, never asks for credentials, and
makes no network request at all. It reads one JSON file out of your repository and renders it.

## How it works

The work splits in two, along the line where judgement is needed:

|     | Terraform → model                                                    | model → pixels        |
| --- | -------------------------------------------------------------------- | --------------------- |
|     | the `devops-tools` plugin's skills                                   | the Electron app      |
|     | Claude reads your `.tf` files and writes `.claude/devops-tools.json` | React Flow renders it |

Terraform is mostly attachment resources. `aws_s3_bucket_versioning`,
`aws_vpc_security_group_ingress_rule`, `aws_route_table_association` — none of those is a box on a
whiteboard; they are properties of a box, or a line between two. A parser draws thirty nodes for
what a person would draw as six, which is why the model is generated by a skill that can make that
call, and why every resource it folds away is recorded in `folded[]` so you can check its work.

`.claude/devops-tools.json` is committed. That is the point: the diagram versions with the
infrastructure, and an architecture change shows up in the same pull request as the Terraform that
caused it.

## Installing

### Requirements

|                 |                                                                                         |
| --------------- | --------------------------------------------------------------------------------------- |
| **Node**        | 22 or newer (`node -v`)                                                                 |
| **pnpm**        | 11.9 — pinned in `package.json` as `packageManager`, so `corepack enable` is enough     |
| **just**        | optional, for the command shortcuts below — [casey/just](https://github.com/casey/just) |
| **Claude Code** | for the skills that generate a board                                                    |

There is no installer yet. The app runs from source.

### 1. Install dependencies

```bash
git clone git@github.com:sdaigle-lichens/devops-tools.git ~/gits/devops-tools
cd ~/gits/devops-tools
just install          # or: pnpm install
```

### 2. Linux only — fix the Electron sandbox bit

pnpm does not preserve the setuid bit on Electron's sandbox helper, and the app aborts on launch
with _"The SUID sandbox helper binary was found, but is not configured correctly."_ It needs root,
once per install that re-extracts Electron:

```bash
sudo chown root:root node_modules/.pnpm/electron@*/node_modules/electron/dist/chrome-sandbox
sudo chmod 4755 node_modules/.pnpm/electron@*/node_modules/electron/dist/chrome-sandbox
```

`just sandbox-help` prints those and shows the file's current state. Afterwards `ls -l` should read
`-rwsr-xr-x` and `root root`. **Do not work around it with `--no-sandbox`** — renderer isolation
from the OS is a property `test/isolation.test.ts` spends four assertions defending.

### 3. Add the marketplace and install the plugin

This repository is itself a Claude Code plugin marketplace — `.claude-plugin/marketplace.json` is
its manifest, and it publishes one plugin, `devops-tools`. Adding the marketplace tells Claude
Code where to find it; installing the plugin is a second, separate step.

From inside a Claude Code session:

```
/plugin marketplace add sdaigle-lichens/devops-tools
/plugin install devops-tools@devops-tools
```

Or from a terminal, without opening a session:

```bash
claude plugin marketplace add sdaigle-lichens/devops-tools
claude plugin install devops-tools@devops-tools
```

`devops-tools@devops-tools` reads _plugin `devops-tools`, from marketplace `devops-tools`_ — the
two names are the same here because the repo publishes a single plugin named after itself.

**Working on the plugin itself?** Point the marketplace at your clone instead of at GitHub, so
edits to a `SKILL.md` take effect without pushing:

```
/plugin marketplace add ~/gits/devops-tools
```

Only one of the two can be registered under the name `devops-tools` at a time — run
`claude plugin marketplace remove devops-tools` before switching between them.

Both manifests are checkable, and worth checking after any edit to either:

```bash
claude plugin validate .                    # the marketplace manifest
claude plugin validate plugins/devops-tools # the plugin manifest
```

### 4. Check it worked

```bash
claude plugin marketplace list    # devops-tools, and where it points
claude plugin list                # devops-tools should be installed
```

In a session, `/devops-tools:` then completes to the two skills.

To pick up changes published here later:

```bash
claude plugin marketplace update devops-tools
claude plugin update devops-tools
```

## Getting started

### 1. Map a project

In a Claude Code session inside a repository that manages AWS with Terraform:

```
/devops-tools:init-devops-tools
```

It writes `.claude/devops-tools.json`. Commit it.

After a Terraform change:

```
/devops-tools:update-devops-tools
```

### 2. Open it

```bash
just dev              # or: pnpm dev
```

Pick the project from the home screen. Click any element to see its full specs in the side panel.

If the app is already open on that project when you run a skill, the canvas updates on its own —
the main process watches the board file.

## Development

`just` from the repo root lists every command. The ones you need day to day:

| command                                      | what it does                                                           |
| -------------------------------------------- | ---------------------------------------------------------------------- |
| `just dev`                                   | run the app with HMR on the renderer                                   |
| `just build`                                 | build main / preload / renderer into `apps/devops-tools/out/`          |
| `just start`                                 | build, then run it the way a real launch does — `out/`, over `file://` |
| `just verify`                                | prettier `--check`, both typechecks, vitest — the full pre-PR check    |
| `just format`                                | prettier `--write`                                                     |
| `just test` / `just lint` / `just typecheck` | the parts of `verify`, individually                                    |
| `just probe`                                 | drive the packaged app in a real window and assert 24 things about it  |
| `just validate [path]`                       | check a board against the schema the app enforces                      |
| `just layout [path]`                         | recompute every position and size in a board from its graph            |
| `just validate-plugin`                       | check the marketplace and plugin manifests                             |
| `just build-plugin-libs`                     | regenerate the plugin's schema bundle                                  |
| `just clean`                                 | drop build output and turbo's local cache                              |

Each wraps a pnpm script, so `pnpm dev`, `pnpm verify` and friends work identically if you would
rather not install `just`.

### Testing

`pnpm test` covers the schema, the loader and the model→React Flow adapter — everything that can be
decided without a browser. It cannot reach the canvas, which is what `just probe` is for: React
Flow measures the DOM, the layout script places siblings using sizes it _assumed_, and a container
is painted over the whole area its children occupy. Its first run found two real defects that every
unit test passed straight through. See
`apps/devops-tools/.claude/skills/test-devops-tools/SKILL.md`.

### The schema is generated into the plugin

The board schema lives in `apps/devops-tools/src/core/board-schema.ts` and is the single source of
truth. The plugin's validator runs off a CJS bundle generated from it, because it executes inside
the _user's_ repository under bare `node` with no `node_modules` of ours:

```bash
just build-plugin-libs
```

Run that after any schema change, and commit the regenerated
`plugins/devops-tools/scripts/lib/board-schema.cjs`. It fails quietly — the stale bundle keeps
working and every test stays green, and the only symptom is that skills start validating boards
against last month's rules.

## Scope

AWS only. Read-only. One architecture per board — point the skill at one Terraform root module, not
at a directory holding several environments.

Not in this version: AWS service icons, search and filter, a minimap, an installer.
